# 基准说明

`npm run benchmark` 不是市场效果证明，而是一个可重复的防误判回归集。它在临时目录中逐例创建任务、验收契约和受保护文件，锁定后运行校验，再比较实际四态结论。

## 20 个案例

| 类别 | 案例 | 期望 |
|---|---|---|
| 命令 | 正常通过 | VERIFIED |
| 命令 | 非零退出 | FAILED |
| 命令 | 超时 | BLOCKED |
| 命令 | 缺少必含输出 | FAILED |
| 命令 | 出现禁用输出 | FAILED |
| 命令 | 可选检查失败 | VERIFIED |
| 文件 | 文件存在 | VERIFIED |
| 文件 | 文件缺失 | FAILED |
| 文件 | 出现禁用文本 | FAILED |
| 文件 | 大小不足 | FAILED |
| 完整性 | 缺少锁 | UNVERIFIED |
| 完整性 | 受保护验收被改 | UNVERIFIED |
| 完整性 | 配置被改 | UNVERIFIED |
| 完整性 | 任务被改 | UNVERIFIED |
| HTTP | 状态与正文通过 | VERIFIED |
| HTTP | 状态不符 | FAILED |
| HTTP | 正文不符 | FAILED |
| HTTP | 服务启动即崩溃 | BLOCKED |
| HTTP | 启动前已有旧服务 | BLOCKED |
| 新鲜度 | 验证后源码变化 | UNVERIFIED |

## 指标

- `Correct verdicts`：实际状态等于预设状态的案例数。
- `False VERIFIED verdicts`：实际给出 `VERIFIED`，但预设不是 `VERIFIED` 的案例数。这是最危险的错误。

输出同时写入机器可读 JSON 和 Markdown。仓库 CI 要求 20/20 且 `False VERIFIED=0`。

## 不能说明什么

受控基准只证明实现对已列举机制按预期工作。它不能证明真实用户需要该产品，也不能代表未知框架、操作系统和复杂仓库。下一阶段必须收集真实代理任务中的漏检、误报、配置成本和阻塞率。
